## 3. 段階ごとの作業

### 3.1 2番目: Bing・GSC

設計は [data_sources.md](data_sources.md) §1・§3・§4・§6、[database_design.md](database_design.md) §4・§5、画面は [screen_design.md](screen_design.md) §4・§7（2026-11-26 にワイヤーフレームで決めた）。

- [ ] テーブルとマイグレーション（`sync_runs`・GSC の3表・Bing の3表。Bing は API の中身を JSON の列にも残す）
- [ ] サイト設定に GSC と Bing の紐づけを足す（画面はデモで作った。2026-11-27。残りは API と DB。[technical_design.md](technical_design.md) §6.4）
  - GSC: 列は GA4 と分ける。追加のときに、GA4 のウェブのデータストリームと同じドメインのサイトを選んでおき、ログインしたアカウントが見られるサイトの一覧から選び直せる（`webmasters.readonly` はログインのときにもらい済み）。Search Console API を GCP で有効にする（人がやる）
  - Bing: API キーを入れ、そのキーで見られる Bing のサイトから選ぶ。キーは利用者ごとに1つで、一度入れたキーはほかのサイトでも選べる（暗号化して `connections` に入れる。OAuth は外販の準備のとき）
- [ ] 日次のバッチ（毎回「取得済みの最終日の3日前」から今日までを取り直す。取得ログ。失敗した日は次回に取り直す）
  - VPS に出すまでは手元でコマンドを打って動かす。毎日でなくても、間があいた分はまとめて取るので抜けは埋まる。Bing はページ別が13週・日次が約98日しかさかのぼれないので、少なくとも数週間に1回は動かす
- [ ] 過去分の取り込み（GSC は16ヶ月前まで、Bing は API が返す範囲）
- [ ] GSC のクエリの整理（翌月8日以降に、その月の表示回数が10回未満のクエリを消す）
- [ ] DB のバックアップ（`pg_dump` を DB の置き場所の外へ。VPS に出すまでは手元の DB が対象）。**ここから DB が、取り直せないデータの唯一の置き場所になる**
- [ ] SEO の画面（`/seo`。Google と Bing を切り替える。合計とサイトのカード、日ごとの推移、クエリ、ページ、Bing のクロールとインデックス）。見た目と部品は、デモ（`/demo/seo`）で先に作った（2026-11-26）。本物は `GET /api/seo` を同じ応答の形で作り（[technical_design.md](technical_design.md) §6.3）、ヘッダーのメニューに足す。集計は、4番目の問い合わせ指定の仕組みのうち、この画面に要る分（GSC・Bing の日ごと・クエリ・ページの集計と比較）を先に作って使う
- [ ] 作る前に確かめること（[data_sources.md](data_sources.md) §7 の GSC・Bing の項目）
- いったん置いておく（2026-11-26 利用者の決定）: データの状態の画面（いつまでのデータがあるか、最後に取り込んだ日時）と「いま取り込む」ボタン

- [ ] VPS を整える（人がやる。手順は私が書く）

  - `/etc/glance/glance.env`（root・600）

## 5. 注意

- **Bing と GSC の古い日は、待つほど消える**（§2）。手元でバッチを動かすのを、数週間以上あけない。
- **VPS に出すまでは、手元の DB が唯一の置き場所**: 手元の DB（Docker のボリューム）を消すと、Bing と16ヶ月より前の GSC は戻らない。バックアップを手元の外に置く。
- **同意画面が「テスト」のうちは、更新トークンが7日で切れる。** 手元では週に1回ログインし直す。手元のバッチも、トークンが切れていると取れない（ログインし直してから動かす）。VPS に出すときに「本番」にする。
- **VPS のメモリ**: Glance は API だけが常駐し、約0.15GB 増える見込み。足りなくなったら 8GB のプランに上げる（[infrastructure_design.md](infrastructure_design.md) §3）。
- **本番の作業は人がやる**: VPS・Cloudflare・GCP の設定と反映は、私が手順とスクリプトを用意し、実行は人が行う。
