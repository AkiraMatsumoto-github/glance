# glance 画面設計

作成日: 2026-11-26
状態: 初版（実装前）。1番目の段階（リアルタイム画面）で作る3画面を書く。全体サマリー・チャット・ダッシュボードの画面は、その段階の前に足す。

画面の機能は [overview.md](overview.md) §4、API は [technical_design.md](technical_design.md) §6、リアルタイムのデータは [data_sources.md](data_sources.md) §5。

---

## 1. 共通

- **ヘッダー**: 左に「Glance」とメニュー（リアルタイム、SEO、サイト設定）、右にログイン中のメールアドレスとログアウト。全体サマリー・チャット・ダッシュボードは、作った段階でメニューに足す。スクロールしても画面の上に固定する（2026-11-26）。スマホでは横幅が足りないので、「Glance」の字を出さず、「ログアウト」は印（アイコン）だけにする。それでも入りきらない狭い画面では、メニューの中だけ横にスクロールする（2026-11-27）。
- **固定バー**: 画面全体に効く操作（SEO の期間・比べる・Google/Bing、リアルタイムの「更新」、サイト設定の「サイトを追加」）は、ヘッダーのすぐ下の固定バーに置き、スクロールしても常に出す（2026-11-26 利用者の決定。どの画面も同じ形）。画面の端から端まで白い面と下の線で、ヘッダーの2段目のように見せる。左に条件（SEO の Google/Bing・期間・比べる）、右にいつのデータかと操作のボタンを置く。データを取り直す画面（リアルタイム・SEO）は、右端を「更新」でそろえる（2026-11-27 利用者の決定）。画面の題は、ヘッダーのメニューでどの画面かわかるので画面には出さず、読み上げ用だけにする（2026-11-27 利用者の決定）。
- **時刻**: すべて日本時間で出す。
- **スマホ**: 表は横にスクロールさせる。グラフは画面の幅に合わせて縮める。
- **文字の表示**: タイトルなど取り込んだ文字は、そのまま文字として出す（HTML として描画しない。[overview.md](overview.md) §5）。

## 2. ログイン（`/login`）

```
┌──────────────────────────────┐
│            Glance              │
│                                │
│     [ Google でログイン ]        │
│  （エラーのときだけ、ここに出す）   │
│ ────────────────────────────── │
│   [ ログインせずにデモを見る ]     │
│  ダミーの数字で、リアルタイムの…   │
└──────────────────────────────┘
```

「ログインせずにデモを見る」は、デモの画面（§6）へ移る（2026-11-26 利用者の決定）。

| 場合 | 出す文 |
|---|---|
| 許可リストにないアカウント | このアカウントは使えません。別の Google アカウントでログインしてください。 |
| 同意画面で中止した | ログインを中止しました。 |
| 許可が切れた（`reauth_required`） | Google の許可が切れました。ログインし直してください。 |
| その他 | ログインできませんでした。時間をおいてもう一度試してください。 |

（数字は例）

**各部**

- **UU**: GA4 のアクティブユーザー（`activeUsers`）。リアルタイム API で取れるユーザー数はこれだけ。
- **取得した時刻と「更新」**: 固定バー（§1）の右に置く。左は「直近30分」。開いたときに1回取る。あとは「更新」を押したときだけ取り直す。取っている間は「更新」を押せなくし、画面の真ん中に「取得中…」の印を出す。前の数字はそのまま出し、取っている間もほかの操作はできる。ほかの画面（サイト設定など）から戻ったときは、前に取った数字（ブラウザのメモリにだけ置く。読み込み直すと消える）をすぐ出してから取り直す（2026-11-26 利用者の決定）。
- **数字のカード**: 直近30分の PV と UU を大きく出し、キーイベントを小さく添える（5分の数字は出さない。2026-11-26 利用者の決定）。
  - 上に合計のカードを横幅いっぱいに置き、数字を大きくする（36px）。その下に、サイト設定の並び順でサイトのカードを並べる（PC は5列、タブレット幅は3列、スマホは2列）。
  - 合計は、選んだサイトを足したもの（取得できなかったサイトは入らない）。名前の横に「選んだ ◯ サイト」と出す。UU の合計は、サイトごとの人数を足したもの。
  - 取得できなかったサイトのカードには、アイコンと「取得できませんでした（理由）」を出す。
- **出すサイトの選択**: 各サイトのカードの名前の前に、チェックボックスを置く（2026-11-26 利用者の決定。グラフの上の選択の行はやめた）。**合計のカード、分ごとの推移、デバイス・国の内訳、いま見られているページに効く。**
  - チェックボックスの枠と塗りは、そのサイトの線の色。カードは選ぶためのもので、凡例は各グラフの題の下に出す（下記）。
  - カードのどこを押してもチェックボックスが切り替わる（2026-11-26 利用者の決定）。押せるカードは、ホバーで面を灰色にする。取得できなかったサイトのカードは押せない。
  - 外したサイトのカードは、数字を薄くする（数字は出したまま）。
  - 初めは全部オン。「更新」を押しても選んだ状態は保つ。画面を開き直すと全部オンに戻る。
  - 切り替えは画面の中だけで行い、API は呼ばない。
  - 取得できなかったサイトは、チェックボックスを押せなくする。
  - 全部オフにしたら、グラフとページの一覧の枠に「サイトを選んでください」と出す。
  - 合計のカードのチェックボックス（墨色。初めはオン）は、分ごとの推移に合計の線を出すかどうかを決める。合計のカードの数字は、オフにしても出したまま。
- **分ごとの推移**: 折れ線で、選んだサイトごとに1本と、合計の線（墨色）。横軸は30分前から今まで。縦軸の目盛りは、出している線に合わせて付け直す。
  - 各分の値に丸い点を出す（どこで折れているかを見えるようにする）。ホバーのカードの最後に合計を出す。
  - **指標は PV と UU を切り替える**（グラフの上のボタン。初めは PV）。切り替えは画面の中だけで行い、API は呼ばない。「更新」を押しても選んだ指標は保つ。
  - 分ごとの UU は、その1分の間に来た人数。同じ人が何分にもまたがるので、分ごとの UU を足しても30分の UU にはならない（表の UU は別に取った値）。
- **デバイス・国の内訳**: 直近30分の UU の割合を（ユーザーの属性なので PV は出さない。2026-11-26 利用者の決定）、サイトごとに1本の帯グラフ（100% の積み上げ）で並べる。PC では2つを横に並べ、スマホでは縦に積む。
  - デバイスの区分は、スマホ・PC・タブレット・その他。国の区分は、選んだサイトを合わせて UU の多い3か国と「その他」（どのサイトの帯も同じ区分）。
  - 区分の色は墨色の濃淡4段（サイトの色とは混ぜない）。割合が12%以上の区分には帯の中に割合を書く。ホバーでは、折れ線グラフと同じ形のカードに、区分とサイト名、UU（割合）を出す。割合は、区分の UU を足した数に対する割合（同じ人が複数のデバイスから見ると、それぞれに数える）。
  - 国には、Zaraz で判定がずれることを注記する（[data_sources.md](data_sources.md) §5）。
- **イベント**: イベント名ごとの直近30分の回数を、多い順に横棒で10件並べる（2026-11-26 利用者の決定）。棒の中は、選んだサイトごとの色で積み上げる。11件目からは「ほかに ◯ 種類」と書く。
  - 棒の長さは、いちばん多いイベントに対する比。棒の右に合計の回数を書く。
  - イベント名は、GA4 が自動で送るもの・よく使う推奨イベントには日本語の名前を付け、元の名前を小さく添える（page_view → ページ表示）。独自のイベントは元の名前のまま。
  - ホバーでは、折れ線グラフと同じ形のカードに、サイトごとの回数と合計を出す。
- **いま見られているページ**: 選んだサイトのページをまとめて、PV の多い順に20件。PV と UU を並べて出す。タイトルはそのまま出し、長いものは省略して、ホバーで全文を出す。
  - ページはリンクにしない（2026-11-26 利用者の決定）。リアルタイムの API はページのタイトルしか返さず、URL を作るには通常の API でタイトルとパスを突き合わせる必要があり、公開して間もないページはリンクにできないため。
  - サイトごとの上位20件（API の応答）から、画面で選んだサイトの分を合わせて並べ直す。どのサイトの組み合わせでも、上位20件はこの中に入る。
- **「AI に聞く」**: 5番目の段階（チャットを作るとき）に、「更新」の隣に足す（[ai_query_design.md](ai_query_design.md) §6.3）。

**状態ごとの出し方**

| 状態 | 出し方 |
|---|---|
| 初めて取っている間 | 画面の真ん中に「取得中…」の印だけを出す |
| 一部のサイトが失敗 | そのサイトの行に「取得できませんでした（理由）」。理由は時間切れ、権限がない、上限に当たった、その他 |
| 全サイトが失敗 | 表の上に「取得できませんでした。時間をおいて更新してください」 |
| 許可が切れた | ログイン画面へ移し、理由を出す（§2） |
| サイトが1つもない | 「サイト設定から GA4 のプロパティを追加してください」と、サイト設定への案内 |

## 4. サイト設定（`/settings/sites`）

```
┌ Glance  リアルタイム  SEO  サイト設定 ─────────────────────────────── user@… ログアウト ┐
├                                                                        [ サイトを追加 ] ┤
├─────────────────────────────────────────────────────────────────────────────────────────┤
│ 並び │ 名前        │ GA4       │ Search Console         │ Bing                   │      │
│ ↑↓   │ [LogiShift] │ 123456789 │ ✓ 連携あり [変更]      │ ✓ 連携あり [変更]      │ 削除 │
│ ↑↓   │ [TechShift] │ 234567890 │ 連携なし [設定する]    │ 連携なし [設定する]    │ 削除 │
└─────────────────────────────────────────────────────────────────────────────────────────┘

「サイトを追加」                          「設定する」「変更」（Search Console）
┌ サイトを追加 ─────────────────┐       ┌ Search Console のサイトを選ぶ ─┐
│ LogiShift     123456789  追加済み │       │ ○ sc-domain:logishift…         │
│ TechShift     234567890  [追加]   │       │ ● sc-domain:techshift…         │
│  Search Console [sc-domain:tech… ▾]│       │ ○ https://blog.logishift…/     │
│ NewSite       345678901  [追加]   │       │ ○ 紐づけない                   │
│  Search Console [紐づけない ▾]     │       │                [やめる] [保存] │
│  同じドメインのサイトが見つかりません│       └─────────────────────────┘
└────────────────────────────┘
                                          「設定する」「変更」（Bing）
                                          ┌ Bing を設定 ─────────────────┐
                                          │ API キー                         │
                                          │ ● LogiShift 用 末尾 1111 [入れ直す]│
                                          │ ○ 新しいキーを追加               │
                                          │   [名前] [API キー] [キーを保存] │
                                          │ 「設定」→「API アクセス」で発行  │
                                          │ サイト ○ https://logishift…/    │
                                          │        ● https://techshift…/    │
                                          │        ○ 紐づけない              │
                                          │                [やめる] [保存]   │
                                          └─────────────────────────┘
```

（ID とサイトは表示の例）

- **サイトを追加**: ログインしたアカウントが見られる GA4 のプロパティを、アカウントごとにまとめて一覧で出す。選ぶとサイトとして追加する。同じドメインの Search Console のサイトも一緒に紐づける（下の「Search Console」）。名前とタイムゾーンはプロパティから取る（タイムゾーンは取り込みで使うだけで、表には出さない。2026-11-27 利用者の決定）。追加済みのプロパティは選べなくする。
- **名前**: その場で編集できる。初めはプロパティの名前。
- **並び**: リアルタイムの表とグラフの色の順になる。
- **削除**: 確かめてから消す。取り込んだ Search Console・Bing の数字も一緒に消えること、Bing の過去の数字は取り直せないことを、確認の文に出す（2026-11-27 利用者の決定。[database_design.md](database_design.md) §2）。連携を外す（「紐づけない」）だけなら、取り込んだ数字は残す。
- **GA4・Search Console・Bing は列を分ける**（見やすさのため。2026-11-27 利用者の決定）。GA4 と Search Console は同じ Google のログインと許可で読むので、紐づけは追加のときに一緒に行う。DB では、取り込みが別々なので2つの接続（`connections` の `ga4`・`gsc`）として持つ。
- **Search Console・Bing の列は「連携あり／連携なし」だけを出す**（紐づけ先の URL は表で見ても役に立たないため。2026-11-27 利用者の決定）。連携ありは、成功の色のチェックの印と文で出し、ホバーで紐づけ先の URL を出す。横のボタンは、連携ありなら「変更」、連携なしなら「設定する」。オン・オフの切り替えにしないのは、オンにするにはサイトを選ぶ（Bing はキーも入れる）必要があり、押すだけでは済まないため。
- **Search Console**:
  - 追加のときに、GA4 のプロパティのウェブのデータストリームの URL と同じドメインの Search Console のサイト（`sc-domain:ドメイン`、またはそのドメインの URL のサイト）を選んでおく。見つからないとき・2つ以上あるときは「紐づけない」を初めの値にし、「同じドメインのサイトが見つかりません」と出す。追加の一覧の中で、ログインしたアカウントが見られるサイトから選び直せる。
  - ドメインのプロパティ（`sc-domain:`）と URL のプロパティが両方あるときは、ドメインのほうを選ぶ（2026-11-27 利用者の決定。[data_sources.md](data_sources.md) §3）。
  - 追加した後は、表の「変更」（連携なしなら「設定する」）で選び直す。最後に「紐づけない」を置く。連携なしのサイトで開いたときは、同じ決まりで選んだサイトを初めから選んでおく（すでに追加済みのサイトは連携なしから始まるため）。
- **Bing**: 「設定する」（紐づけ済みなら「変更」）で、使う API キーを選び（初めてなら名前を付けて入れる）、そのキーで見られる Bing のサイトから1つ選ぶ。キーは顧客ごとに複数持て、名前（例「LogiShift 用」）で選ぶ（サイトを別々に売ることがあり、Bing のアカウントが分かれうるため。2026-11-27 利用者の決定）。一度入れたキーは、ほかのサイトでもそのまま選べる。キーは画面に出さず、名前と末尾4文字だけを出す。変えるときは「入れ直す」で入れ直し、そのキーを使う全サイトに効く（2026-11-27 利用者の決定）。キーの発行場所（Bing Webmaster Tools の「設定」→「API アクセス」）を欄の下に書く。認証は API キー（OAuth は外販の準備のとき。[data_sources.md](data_sources.md) §4）。
- 画面はデモで先に作った（2026-11-27）。Search Console・Bing の列は、API がサイトの紐づけ（`links`）を返すときだけ出す。本物の API は紐づけの保存を作るまで返さないので、本物の画面は GA4 だけを出す（[technical_design.md](technical_design.md) §6.4、[roadmap.md](roadmap.md) §3.1）。
- データの状態（いつまでのデータがあるか、最後に取り込んだ日時）と「いま取り込む」ボタンの画面は、いったん置いておく（2026-11-26。[roadmap.md](roadmap.md) §3.1）。

## 5. グラフの見た目（GA4 に近づける）

Recharts の設定。[overview.md](overview.md) §3。

| 項目 | 設定 |
|---|---|
| 補助線 | 横だけ。薄いグレー |
| 縦軸 | 目盛りは右側。軸の線は引かない |
| 線 | 2px。各値に丸い点（直径 6px・白い縁）。ホバーした点は大きくする |
| 比較期間 | 同じ色の薄い破線（不透明度 45%）。点は付けない。重ねるかは選べる（SEO の日ごとの推移で使う。§7） |
| ホバー | 縦線を引き、その時点の全系列の値を1枚のカードに並べる（系列の色の丸、名前、値）。カードは React のコンポーネントで書く |
| 凡例 | グラフの題のすぐ下に、色の丸と名前を横に並べる（選んでいるサイトだけ。分ごとの推移は、合計の線を出しているときは「合計」も）。デバイス・国の帯グラフは、区分（スマホ・日本など）の凡例を同じ位置に出す |
| 合計 | 墨色の線。サイトの線の上に描く |
| 色 | サイトの色（`--series-1`〜`--series-8`）を、サイトの並び順に割り当てる。9サイト目からは灰色の「その他」（[design_guideline.md](design_guideline.md) §2.2） |
| 動き | 描き始めのアニメーションは切る |

画面全体の色・文字・余白・部品・グラフの決まりは [design_guideline.md](design_guideline.md)。

## 6. デモ（`/demo`・`/demo/seo`・`/demo/settings/sites`）

**決めたこと**

- **Google と Bing は切り替える**（足し合わせない。2026-11-26 利用者の決定）。取れる指標が違うため（Bing は日ごとの掲載順位がなく、クエリも今は取らない）。
- **期間**: 直近7日・直近28日・今月・先月・指定。**比べる**: 前の期間・前年・比べない（2026-11-26 利用者の決定）。期間・比べる・Google/Bing の切り替えは、ヘッダーのすぐ下の固定バーにまとめ、スクロールしても常に出す（2026-11-26 利用者の決定。下に浮かせる形・スクロールしたら縮む形と比べて、中身に重ならず、見た目が1通りで済むこの形にした）。
- **いつまでのデータか**: 固定バーの右、「更新」の隣に「◯月◯日までのデータ」と出す（リアルタイムの「◯ に取得」と同じ位置。Google と Bing で違う）（取得ログから。GSC は確定まで2〜3日かかる）。
- **合計のカード**: 選んだサイトを足す。CTR は「クリック ÷ 表示回数」、掲載順位は表示回数の重みつき平均で出す（[database_design.md](database_design.md) §6）。比べる期間との差を、クリック・表示回数は増減率、CTR は pt で出す。
- **掲載順位**: 数字が小さいほど上なので、増減は「◯ 上がった／下がった」と書く（+／- は使わない）。
- **サイトのカード**: チェックボックスで選ぶ。選んだサイトが、合計・推移・クエリ・ページに効く（リアルタイムと同じ）。
- **日ごとの推移**: 指標を切り替える。比べる期間は、「比べる期間を重ねる」を選んだときだけ、同じ色の薄い破線で重ねる（初めは重ねない。5サイトと合計で線が12本になり読みにくいため。2026-11-26 利用者の決定）。
- **クエリ・ページ**: 選んだサイトをまとめて、クリックの多い順に20件。「もっと見る」で100件まで。「増えた／減った」で、比べる期間との差の大きい順に並べ替える。クエリは、Google が伏せたものと少ないもの（月ごとの整理）を含まない（[data_sources.md](data_sources.md) §3）。ページはタイトルとパスを並べる。
- **Bing のときだけ**: クロールとインデックスの推移を出す（下の「インデックス」の節の中）。インデックス数・被リンク数は足さず、期間の最後の値を出す。
- **インデックス**（2026-11-28 利用者の決定）: 日ごとの推移のすぐ下に、Google と Bing で同じ形で出す。
  - サイトごとの表: サイト・サイトマップの URL・インデックス・割合（インデックス ÷ サイトマップの URL）。2サイト以上なら合計の行。サイトマップを読めていないサイトは「サイトマップを読めていません」。
  - インデックスは、Google は期間中に検索に1回でも出た（imp 1回以上の）ページのうちサイトマップにあるものの数（列の名前は「検索に出たページ（imp 1回以上）」）。Search Console の API ではインデックス登録の数（管理画面の「ページのインデックス登録」）を取れないための目安で、出ていないページは、インデックスされていないか、順位が低くて出ていないかのどちらか（区別できない）。Bing は、Bing のインデックス数（期間の最後の日）。Bing はサイトマップに無いページ（カテゴリなど、消した古いページ）もインデックスしているので、割合が 100% を超えることがある。
  - 推移: Google は日ごとの検索に出たページ数、Bing はクロールの数字（インデックス数・クロール数・クロールエラーを切り替え）。サイトごとの線で、合計の線は出さない。グラフの題と凡例は付けない（サイトの色は、すぐ上の表の色の丸で読む。Bing は切り替えだけを出す。2026-11-28 利用者の決定）。Bing の「クロールとインデックス」の節は、ここにまとめた。
  - 検索に出ていないページの一覧は出さない（2026-11-28 利用者の決定）。
- **本物（2026-11-27 に作った）**: 出すサイトは、その検索エンジンを連携したサイトだけ。連携したサイトが無ければ「◯と連携しているサイトがありません」とサイト設定へのリンクを出し、まだ取り込んでいなければ、取り込みのコマンドを動かすよう出す。ページはタイトルを持っていないので、パスを名前にする（GA4 の取り込みを作ったらタイトルを出す）。Bing のページ別は週ごとなので、週の日付が期間に入る週を足す。

**デモで作ったときに決めた細かいところ**（2026-11-26。[technical_design.md](technical_design.md) §6.3）

- **固定バー**: 画面の端から端まで白い面と下の線を引き、ヘッダーの2段目のように見せる（高さは約74px。ヘッダーと合わせて約130px）。1行目の左に Google/Bing（左端）・期間・比べる、右にいつまでのデータか・「更新」（右端）、2行目に「2026年10月27日〜11月23日（28日間）を 2026年9月29日〜10月26日 と比べる」のように実際の期間を出す。実際の期間は、比べる期間の決め方（今月・先月は前の月の全体など。[api_design.md](api_design.md) §1）が見てわかるようにするため。スマホでは「期間」「比べる」の文字を読み上げだけにして1行目を操作だけにし、「更新」は2行目の右、いつまでのデータかは2行目の文の終わりに回す（バーは約110px、ヘッダーと合わせて約165px。360px 幅の画面と、指定を選んだときは、操作が2行になる分だけ伸びる）。
- **更新**: 開いたとき・条件を変えたときに取るほか、「更新」で同じ条件のまま取り直す（取り込みが進んでいれば新しい日が入る）。取っている間は「取得中…」にして押せなくし、前の数字はそのまま出す（リアルタイムと同じ。2026-11-27 利用者の決定）。
- **指定**: 始まりと終わりの日付を選ぶ。指定に切り替えたときは、いま出している期間を初めの値にする。終わりはデータがある最終日までに縮める。始まりが終わりより後などのときは、理由を画面に出す。
- **合計とサイトのカード**: 合計は、クリック・表示回数・CTR・平均掲載順位を同じ大きさで並べる。サイトのカードは、クリック（と比べる期間との差）を大きく、表示回数と掲載順位を小さく出す。表示回数は1万を超えたら「38.5万」の形にする。比べる期間と同じなら「±0%」「±0pt」「変わらない」と書く。
- **日ごとの推移**: 「比べる期間を重ねる」のチェックボックスは、題と指標の切り替えの行の右に置く（比べないときは出さない）。比べる期間の破線は、不透明度 45% にして、期間の何日目かでそろえて重ねる（期間の長さが違うときは、短いほうの終わりで切れる）。破線には点を付けない（この期間の線と見分けるため）。重ねているときは、凡例の最後に「比べる期間」（破線）を足し、ホバーのカードに、この期間の日と比べる期間の日を2列で並べる（前年と比べるときは、比べる日に年を付ける）。掲載順位は、ほかの指標と同じく数字が小さいほど下に描き（縦軸を逆にしない。2026-11-27 利用者の決定）、値のある範囲に合わせる（0 から始めると線が潰れるため）。
- **クエリ・ページ**: 「前と比べて」の列は、クリックの差（+94 など）。比べる期間にそのサイトの数字が無いときは「—」にし（ホバーで「比べる期間の数字がありません」）、増えた・減ったの並べ替えには入れない。本物は、比べる期間に数字があれば、そのクエリ・ページが無いとき 0 として差を出す。比べないときは、この列と「すべて／増えた／減った」を出さない。ページは、タイトルの下にパスを小さく出す。「もっと見る」を押した後は「上位20件に戻す」。
- **Bing のとき**: 日ごとの推移はクリックと表示回数だけ（CTR・掲載順位の切り替えは出さない）。合計のカードは CTR まで（掲載順位は出さない）。サイトのカードは、掲載順位の代わりにインデックス数（期間の最後の日の値）を出す。クロールとインデックスは、インデックス数・クロール数・クロールエラーを切り替え、サイトごとの線だけを出す（インデックス数は足せないので、合計の線は出さない）。
