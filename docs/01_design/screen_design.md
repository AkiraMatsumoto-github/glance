# glance 画面設計

作成日: 2026-11-26
状態: 初版（実装前）。1番目の段階（リアルタイム画面）で作る3画面を書く。全体サマリー・チャット・ダッシュボードの画面は、その段階の前に足す。

画面の機能は [overview.md](overview.md) §4、API は [technical_design.md](technical_design.md) §6、リアルタイムのデータは [data_sources.md](data_sources.md) §5。

---

## 1. 共通

- **ヘッダー**: 左に「Glance」とメニュー（リアルタイム、サイト設定）、右にログイン中のメールアドレスとログアウト。全体サマリー・チャット・ダッシュボードは、作った段階でメニューに足す。スクロールしても画面の上に固定する（2026-11-26）。
- **時刻**: すべて日本時間で出す。
- **スマホ**: 表は横にスクロールさせる。グラフは画面の幅に合わせて縮める。
- **文字の表示**: タイトルなど取り込んだ文字は、そのまま文字として出す（HTML として描画しない。[overview.md](overview.md) §5）。

## 2. ログイン（`/login`）

```
┌──────────────────────────────┐
│            Glance              │
│                                │
│     [ Google でログイン ]        │
│                                │
│  （エラーのときだけ、ここに出す）   │
└──────────────────────────────┘
```

| 場合 | 出す文 |
|---|---|
| 許可リストにないアカウント | このアカウントは使えません。別の Google アカウントでログインしてください。 |
| 同意画面で中止した | ログインを中止しました。 |
| 許可が切れた（`reauth_required`） | Google の許可が切れました。ログインし直してください。 |
| その他 | ログインできませんでした。時間をおいてもう一度試してください。 |

（数字は例）

**各部**

- **UU**: GA4 のアクティブユーザー（`activeUsers`）。リアルタイム API で取れるユーザー数はこれだけ。
- **取得した時刻と「更新」**: 開いたときに1回取る。あとは「更新」を押したときだけ取り直す。取っている間は「更新」を押せなくし、画面の真ん中に「取得中…」の印を出す。前の数字はそのまま出し、取っている間もほかの操作はできる。ほかの画面（サイト設定など）から戻ったときは、前に取った数字（ブラウザのメモリにだけ置く。読み込み直すと消える）をすぐ出してから取り直す（2026-11-26 利用者の決定）。
- **数字のカード**: 直近30分の PV と UU を大きく出し、キーイベントを小さく添える（5分の数字は出さない。2026-11-26 利用者の決定）。
  - 上に合計のカードを横幅いっぱいに置き、数字を大きくする（36px）。その下に、サイト設定の並び順でサイトのカードを並べる（PC は5列、タブレット幅は3列、スマホは2列）。
  - 合計は、選んだサイトを足したもの（取得できなかったサイトは入らない）。名前の横に「選んだ ◯ サイト」と出す。UU の合計は、サイトごとの人数を足したもの。
  - 取得できなかったサイトのカードには、アイコンと「取得できませんでした（理由）」を出す。
- **出すサイトの選択**: 各サイトのカードの名前の前に、チェックボックスを置く（2026-11-26 利用者の決定。グラフの上の選択の行はやめた）。**合計のカード、分ごとの推移、デバイス・国の内訳、いま見られているページに効く。**
  - チェックボックスの枠と塗りは、そのサイトの線の色。カードは選ぶためのもので、凡例は各グラフの題の下に出す（下記）。
  - カードのどこを押してもチェックボックスが切り替わる（2026-11-26 利用者の決定）。押せるカードは、ホバーで面を灰色にする。取得できなかったサイトのカードは押せない。
  - 外したサイトのカードは、数字を薄くする（数字は出したまま）。
  - 初めは全部オン。「更新」を押しても選んだ状態は保つ。画面を開き直すと全部オンに戻る。
  - 切り替えは画面の中だけで行い、API は呼ばない。
  - 取得できなかったサイトは、チェックボックスを押せなくする。
  - 全部オフにしたら、グラフとページの一覧の枠に「サイトを選んでください」と出す。
  - 合計のカードのチェックボックス（墨色。初めはオン）は、分ごとの推移に合計の線を出すかどうかを決める。合計のカードの数字は、オフにしても出したまま。
- **分ごとの推移**: 折れ線で、選んだサイトごとに1本と、合計の線（墨色）。横軸は30分前から今まで。縦軸の目盛りは、出している線に合わせて付け直す。
  - 各分の値に丸い点を出す（どこで折れているかを見えるようにする）。ホバーのカードの最後に合計を出す。
  - **指標は PV と UU を切り替える**（グラフの上のボタン。初めは PV）。切り替えは画面の中だけで行い、API は呼ばない。「更新」を押しても選んだ指標は保つ。
  - 分ごとの UU は、その1分の間に来た人数。同じ人が何分にもまたがるので、分ごとの UU を足しても30分の UU にはならない（表の UU は別に取った値）。
- **デバイス・国の内訳**: 直近30分の UU の割合を（ユーザーの属性なので PV は出さない。2026-11-26 利用者の決定）、サイトごとに1本の帯グラフ（100% の積み上げ）で並べる。PC では2つを横に並べ、スマホでは縦に積む。
  - デバイスの区分は、スマホ・PC・タブレット・その他。国の区分は、選んだサイトを合わせて UU の多い3か国と「その他」（どのサイトの帯も同じ区分）。
  - 区分の色は墨色の濃淡4段（サイトの色とは混ぜない）。割合が12%以上の区分には帯の中に割合を書く。ホバーでは、折れ線グラフと同じ形のカードに、区分とサイト名、UU（割合）を出す。割合は、区分の UU を足した数に対する割合（同じ人が複数のデバイスから見ると、それぞれに数える）。
  - 国には、Zaraz で判定がずれることを注記する（[data_sources.md](data_sources.md) §5）。
- **イベント**: イベント名ごとの直近30分の回数を、多い順に横棒で10件並べる（2026-11-26 利用者の決定）。棒の中は、選んだサイトごとの色で積み上げる。11件目からは「ほかに ◯ 種類」と書く。
  - 棒の長さは、いちばん多いイベントに対する比。棒の右に合計の回数を書く。
  - イベント名は、GA4 が自動で送るもの・よく使う推奨イベントには日本語の名前を付け、元の名前を小さく添える（page_view → ページ表示）。独自のイベントは元の名前のまま。
  - ホバーでは、折れ線グラフと同じ形のカードに、サイトごとの回数と合計を出す。
- **いま見られているページ**: 選んだサイトのページをまとめて、PV の多い順に20件。PV と UU を並べて出す。タイトルはそのまま出し、長いものは省略して、ホバーで全文を出す。
  - ページはリンクにしない（2026-11-26 利用者の決定）。リアルタイムの API はページのタイトルしか返さず、URL を作るには通常の API でタイトルとパスを突き合わせる必要があり、公開して間もないページはリンクにできないため。
  - サイトごとの上位20件（API の応答）から、画面で選んだサイトの分を合わせて並べ直す。どのサイトの組み合わせでも、上位20件はこの中に入る。
- **「AI に聞く」**: 5番目の段階（チャットを作るとき）に、「更新」の隣に足す（[ai_query_design.md](ai_query_design.md) §6.3）。

**状態ごとの出し方**

| 状態 | 出し方 |
|---|---|
| 初めて取っている間 | 画面の真ん中に「取得中…」の印だけを出す |
| 一部のサイトが失敗 | そのサイトの行に「取得できませんでした（理由）」。理由は時間切れ、権限がない、上限に当たった、その他 |
| 全サイトが失敗 | 表の上に「取得できませんでした。時間をおいて更新してください」 |
| 許可が切れた | ログイン画面へ移し、理由を出す（§2） |
| サイトが1つもない | 「サイト設定から GA4 のプロパティを追加してください」と、サイト設定への案内 |

## 4. サイト設定（`/settings/sites`）

```
┌ Glance  リアルタイム  サイト設定 ─────────────────── user@… ログアウト ┐
│                                                                      │
│ サイト設定                                        [ サイトを追加 ]     │
│                                                                      │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 並び │ 名前（編集できる） │ GA4 プロパティ ID │ タイムゾーン │      │ │
│ │ ↑↓  │ LogiShift         │ 123456789        │ Asia/Tokyo  │ 削除 │ │
│ │ ↑↓  │ TechShift         │ …                │ …           │ 削除 │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

（プロパティ ID は表示の例）

- **サイトを追加**: ログインしたアカウントが見られる GA4 のプロパティを、アカウントごとにまとめて一覧で出す。選ぶとサイトとして追加する。名前とタイムゾーンはプロパティから取る。追加済みのプロパティは選べなくする。
- **名前**: その場で編集できる。初めはプロパティの名前。
- **並び**: リアルタイムの表とグラフの色の順になる。
- **削除**: 確かめてから消す。
- Search Console・Bing の紐づけは、2番目の段階でこの画面に足す。

## 5. グラフの見た目（GA4 に近づける）

Recharts の設定。[overview.md](overview.md) §3。

| 項目 | 設定 |
|---|---|
| 補助線 | 横だけ。薄いグレー |
| 縦軸 | 目盛りは右側。軸の線は引かない |
| 線 | 2px。各値に丸い点（直径 6px・白い縁）。ホバーした点は大きくする |
| 比較期間 | 破線（2番目以降の段階で、比較のあるグラフに使う） |
| ホバー | 縦線を引き、その時点の全系列の値を1枚のカードに並べる（系列の色の丸、名前、値）。カードは React のコンポーネントで書く |
| 凡例 | グラフの題のすぐ下に、色の丸と名前を横に並べる（選んでいるサイトだけ。分ごとの推移は、合計の線を出しているときは「合計」も）。デバイス・国の帯グラフは、区分（スマホ・日本など）の凡例を同じ位置に出す |
| 合計 | 墨色の線。サイトの線の上に描く |
| 色 | サイトの色（`--series-1`〜`--series-8`）を、サイトの並び順に割り当てる。9サイト目からは灰色の「その他」（[design_guideline.md](design_guideline.md) §2.2） |
| 動き | 描き始めのアニメーションは切る |

画面全体の色・文字・余白・部品・グラフの決まりは [design_guideline.md](design_guideline.md)。
